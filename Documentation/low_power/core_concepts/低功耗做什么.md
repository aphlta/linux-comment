可以把系统想成一座城市，低功耗就是在“人少/车少/店没开”的时候，自动做三类事：

1) 让 CPU 少干活（省电的第一大头）

- 让 CPU 早点睡、睡得更深 ：系统没事做时进入不同“睡眠档位”（浅睡=醒得快但省得少；深睡=省得多但唤醒代价大）。对应内核里的 cpuidle。
- 让 CPU 以更合适的速度跑 ：忙的时候提频，闲的时候降频，并且配合电压一起调（DVFS）。对应 cpufreq/OPP。
2) 让外设按需工作（别让“闲着的设备”偷电）

- 很多设备就算你不用也会耗电，比如 GPU、Wi‑Fi、USB、I2C 上的 PMIC、各种传感器。
- Linux 通过 Runtime PM 做“随用随开、用完就关/降功耗”：驱动在用设备前把它 resume，上层不用后让它 autosuspend；同时配合 clock/regulator 把时钟关掉、把电源域关掉或降压。
3) 让整机在“你不用”时进入更省的系统态

- Suspend-to-RAM（常说的待机） ：大部分设备断电/低功耗，内存自刷新，靠中断/事件唤醒。
- Hibernate（休眠到盘） ：把内存内容存到存储里，整机几乎断电（更省，但恢复更慢）。
- 内核的系统睡眠会按严格顺序让各设备进入/退出低功耗，避免“还在调频却把 I2C 先睡了”这种依赖死锁问题。
低功耗最核心的矛盾

- 省电 vs 响应速度/性能 ：睡得越深越省，但醒来越慢；频率越低越省，但跑任务更慢。
- Linux 的工作就是做动态权衡：靠调度器、计时器、I/O、设备驱动的“忙/闲”信号，把系统尽量推向“该省就省”。
