# SoC 低功耗工程：实验室仪器与调试方法实操手册

本文面向 **SoC / 平台低功耗工程师**（含芯片后硅验证、BSP、系统功耗优化），说明常见**测量仪器**的**连接方式、操作顺序、读数含义与典型误区**，并补充 **Linux 内核侧**常用的可观测性与实验方法。  
**原因**：低功耗问题多数是「电流形态 + 时间轴上的事件」不对齐；仪器解决「测到什么」，方法论解决「和谁对齐、如何缩小范围」。

## 零、安全与测量前提

### 0.1 电气安全

- **原因**：实验室电源可输出数十安培，短路可烧毁走线、连接器或芯片。
- **做法**：先确认电压/电流限值再上电；改线时**断电**；大电容轨注意**预充电/浪涌**（按硬件规范操作）。

### 0.2 测量不改变被测对象

- **原因**：长杜邦线、地环路、探头接地夹随便夹，会引入噪声或改变环路稳定性。
- **做法**：尽量短接地、单点参考地；μA 级测量时**优先厂商推荐附件**（分流器、专用电缆）。

### 0.3 可重复性

- **原因**：温度、电池模拟电压、屏幕亮度、射频状态会掩盖 10%～数量级的差异。
- **做法**：记录 **温度、输入电压、固件版本、内核配置、workload**；对比实验**一次只改一个变量**。

## 一、数字万用表（DMM）

### 1.1 用途与边界

- **适合**：各路电源轨电压是否符合预期；**近似静态**或**变化很慢**的平均电流；上电前后漏电档位对比。
- **不适合**：毫秒级以下的电流尖峰、burst、唤醒瞬态（带宽不足，读数会被「平均」掉）。
- **原因**：DMM 在电流档多为**积分式**测量，反映的是窗口内平均，容易漏掉尖峰。

### 1.2 测电压（轨电压）

1. **黑表笔**接板级 **GND 参考面**（低阻抗地），**红表笔**接待测点（PMIC 输出、LDO 输出、测试点）。
2. 量程从大到小，避免挡位过小损坏表（依表说明书）。
3. **负载下**与**空载/睡眠下**各记一次；睡眠异常时常对比「睡眠前后同一轨」是否被意外拉高或拉低。

### 1.3 测电流（串联法）

1. **断电**，将 DMM **串联**进供电回路（电池座、电源线割线、或板载 0Ω 跳线位）。
2. 旋钮到合适电流档；注意 **fuse 额定值**。
3. 上电读数。
- **原因**：电流必须**串联**测量；并联会短路。

### 1.4 常见误区

- **用电压档误测电流**：会损坏设备。
- **在 uA 档用错插孔**：部分表有独立 uA/mA 插孔，插错无读数或烧保险。
- **把 DMM 读数当「峰值电流」**：动态场景需示波器或高速分流方案。

## 二、示波器 + 电流测量

### 2.1 用途

- 观察 **唤醒脉冲宽度**、**周期性尖峰**、**状态切换瞬间**电流。
- 与 **EN 脚、32k、中断线、PMIC interrupt** 等做 **时间对齐**，回答「谁先谁后」。

### 2.2 两种电流获取方式

#### 方式 A：电流探头（霍尔/AC+DC）

1. 探头卡在供电线单根导体上（注意箭头方向与校准）。
2. **消磁/校零**（按探头手册，常需按按钮并在无电流时执行）。
3. 示波器通道设置探头比（A/V 或 mV/A），垂直档位调到噪声可接受且不过载。
- **原因**：探头有**失调**与**温漂**，不测前校零会误判 uA～mA 偏移。

#### 方式 B：分流电阻（shunt）+ 差分或单端

1. 在电源高边或低边串入已知 **R_shunt**（例如 10 mΩ～1 Ω，视电流与可接受压降而定）。
2. 用差分探头测 shunt 两端电压：\(I = V/R\)。
3. **带宽**：小阻值 shunt 搭配寄生电感会在高频高估尖峰；必要时用四线开尔文封装 shunt。
- **原因**：μA 级时电压极小，常需 **前端放大** 或专用电流检测芯片，否则被示波器底噪淹没。

### 2.3 推荐示波器设置思路

1. **采样率**：至少覆盖关心事件边沿的若干倍（例如看 µs 级事件，MS/s 级要留余量）。
2. **记录长度**：单次捕获用长存储；重复事件可用 **触发 + 平均**（平均会降低随机噪声，但会抹平非周期细节，需权衡）。
3. **触发**：用 **GPIO 唤醒脚**、**PMIC PG**、**UART 起始位** 等作为触发源，稳定抓取「唤醒前 → 唤醒后」窗口。
4. **多通道**：一通道电流（或 shunt 电压），其余接关键数字信号；统一 **时基**。

### 2.4 读图与记录

- 标注：**触发电平、时基、探头型号、shunt 阻值、供电电压、温度**。
- 对单次事件：截 **峰值、平台段平均、持续时间**。
- **原因**：没有触发与标注的波形，后续无法与软件 log 对齐。

### 2.5 常见误区

- **地夹乱夹导致环路**：测量高频噪声变大或形态失真。
- **电流探头量程过大**：小电流时分辨率不足，看起来「平直」其实有结构。
- **只看峰值不看占空比**：续航由 **积分** 决定，窄尖峰有时不如长平台耗电。

## 三、功耗分析仪 / 带精密电流读回的可编程电源

### 3.1 用途

- **长时间平均电流**（秒～小时）：待机、播放、下载等业务场景。
- **软件版本 A/B**、**配置 A/B** 的对比；画 **I–t** 曲线看占比。

### 3.2 典型连接

1. 设备由分析仪 **供电输出** 端口供电（或串联在电池路径，依仪器架构）。
2. 设置 **电压**（如 3.8 V）、**电流限**（保护）、必要时 **阶跃/列表** 工况。
3. 使能 **数据记录**（采样率与仪器能力相关；高采样与长记录会占存储）。

### 3.3 操作顺序建议

1. 先 **空载校准/清零**（若支持），再接待测板。
2. 固定 **workload 脚本**（例如循环播放、固定亮度、关后台）。
3. 每种工况记录 **足够长时间**（至少覆盖若干周期事件，如屏幕刷新、心跳）。
4. 导出 CSV，在脚本里算 **平均、分位数、分段积分**。

### 3.4 与示波器分工

- **分析仪**：回答「这 10 分钟平均多少 mA」「睡眠段是否周期性被拉高」。
- **示波器**：回答「拉高那一截里，尖峰多宽、和哪根线对齐」。

### 3.5 常见误区

- **量程自动切换死区**：某些设备在档位切换时有盲区，对比实验要用同一量程策略。
- **USB/辅助供电偷电**：被测系统若仍从 USB 取电，主通道读数会**严重偏低**。
- **线损**：大电流时线压降导致 **芯片端电压** 低于设定，漏电与动态电流都会变。

## 四、源表（SMU）与可编程电源

### 4.1 SMU 典型用途

- 精细 **扫描电压**，观察 **漏电** 随 \(V_{DD}\) 变化（排查异常导通、错误偏置）。
- **限流** 模式下捕捉上电浪涌（配合示波器电流通道更佳）。

### 4.2 基本用法

1. **四线（Kelvin）** 连接（若支持且电流大）：消除引线电阻对电压读数的影响。
2. 设定 **电压、电流合规（compliance）**，防止过压过流。
3. **步进**或 **列表**：例如从 0.8 V 到 1.0 V 每步 10 mV，每步稳定后读电流。
- **原因**：漏电对电压极敏感；扫描可发现「某一电压段异常抬头」。

### 4.3 可编程电源（无 SMU 精度时）

- 用 **回读电流** 做粗粒度场景对比；μA 级以仪器规格为准，不够时回到 **分流 + 示波器** 或专用 uA 表。

## 五、热像仪

### 5.1 用途

- **相对热点**：同一板卡、同一工况，改固件/改时钟前后对比。
- 辅助判断 **意外导通、短路、异常模块常开**（局部发热）。

### 5.2 使用方法

1. **热平衡**：开机后等待至温度趋势变缓再拍（时间依散热条件）。
2. **发射率**：塑封、金属、屏幕设置不同；**对比实验**时尽量固定材料与角度。
3. **距离与视场**：同一距离拍前后两张，避免调色标范围误导。

### 5.3 边界

- 热像仪对 **mW 级** 分布式漏电不敏感；更适合 **局部异常**。
- **原因**：热扩散使空间分辨率与时间分辨率都有限，需与电测交叉验证。

## 六、逻辑分析仪 / 混合信号示波器（MSO）

### 6.1 用途

- 多路 **数字信号**（SPI/I2C 使能、片选、中断）与 **电流波形** 在同一时间轴上**粗对齐**。
- 抓 **总线是否在不该活动时活动**。

### 6.2 逻辑分析仪要点

1. **阈值电压**与目标 IO 电平匹配（1.8 V / 3.3 V）。
2. **采样率**需高于最快关心信号（Nyquist 工程上留足余量）。
3. **探头电容/负载**：过高负载会改变数字边沿或引起误触发，高速总线慎用飞线。

### 6.3 MSO

- 在单台设备上同时看 **模拟（电流/shunt）** 与 **数字**，减少触发对齐难度。

## 七、JTAG / SWD 与片上 Trace

### 7.1 JTAG / SWD

- **用途**：读 **电源/时钟相关寄存器**、核对 **复位默认值**、单步可疑初始化序列。
- **原因**：有时软件 log 未到打印点，寄存器状态已能说明「某域没关」。

### 7.2 基本流程

1. 连接调试器，确认 **链上器件** 与 **IR/DR 长度** 正确。
2. halt → 读时钟门控、电源域状态寄存器 → 与 TRM 位定义对照。
3. 恢复运行，用 **断点** 卡在 `suspend` 前后或驱动 probe 路径。

### 7.3 片上 Trace（ETB/ETM 等，视架构而定）

- **用途**：把 **PC/指令流** 与外部电流波形对齐，定位「谁在唤醒周期里跑」。
- **成本**：接脚、buffer、权限与工具链门槛高；适合难复现或 OS 已挂死类问题。

## 八、软件与内核侧调试手段（Linux / Android 向）

本节说明「在**不拆板**或**互补于电测**」时常用手法。**原因**：许多问题是 **驱动 refcount、wakeirq、timer、DMA** 导致无法进深睡，软件可观测性能直接缩小怀疑范围。

### 8.1 唤醒源与睡眠障碍

- **`/sys/kernel/debug/wakeup_sources`**（或 sysfs 等价接口，视版本与配置）：看 **active_since、event count**，找异常常驻唤醒源。
- **`dmesg`**：`PM: suspend entry` / `PM: suspend exit`、设备失败原因。
- **做法**：suspend 前后各抓一次；对比 **kernel 版本**与 **config**（`CONFIG_PM_DEBUG` 等）。

### 8.2 cpuidle / 空闲统计

- ** sysfs**：各 state 的 **time、usage**（路径随架构/驱动实现略有差异）。
- **解读**：若 shallow state 占比异常高，常与 **timer 粒度、中断、QoS** 有关。

### 8.3 ftrace / tracepoint

- **用途**：`suspend_resume`、`device_pm_callback_start/end`、`power:*` 等事件，看 **谁慢、谁失败**。
- **做法**：缓冲设足够大，抓取单次 suspend；与硬件波形时间对齐时在用户态打 **GPIO 标记**（若可改内核）或在已知点看 **UART 时间戳**。

### 8.4 powertop / perf

- **powertop**：用户态 **C-state、唤醒** 粗览，适合 PC/部分嵌入式发行版。
- **perf**：CPU 热点与 **不必要轮询**；高占用的 idle 轮询会拖垮 residency。

### 8.5 Runtime PM / 时钟 / regulator（概念对齐）

- **Runtime PM**：`usage_count`、autosuspend 延迟；错误配对会导致 **永不 suspend** 或 **频繁 resume**。
- **CCF**：`clk_summary`（debugfs，若开启）看谁持有时钟。
- **regulator**：消费者与电压域是否与硬件电源树一致。

### 8.6 Android 补充（若在 Android 产品岗）

- **Battery Historian / bugreport**：宏观 **wakelock、alarm、job**；与内核 wakeup_sources 交叉验证。
- **原因**：框架层持锁与内核层常驻唤醒源可能不是一一对应，需要两边对齐。

## 九、通用调试方法论

### 9.1 「电流形态 + 时间轴对齐」

1. 先用 **长窗口**（分析仪）确认「是否有周期」「睡眠段是否存在」。
2. 再用 **示波器** 对单次事件展开，选 **触发源**。
3. 软件侧用 **log 时间戳** 或 **GPIO 探针** 与波形对齐。

### 9.2 二分缩小范围

- **硬件**：拔外设、关射频、最小内核、关显示；保留最小启动。
- **软件**：关 DVFS 实验、冻结某子系统驱动、替换为 stub。
- **原因**：低功耗问题组合爆炸，二分是最省时间的结构化手段。

### 9.3 建立「基准曲线库」

- 为 **golden 板**、**golden 固件** 存一份标准 I–t / 波形截图；后续回归对比。
- **原因**：很多问题来自「渐进式回归」，没有基准就无法证明变差。

### 9.4 区分漏电与动态

- **漏电**：频率/负载很低时电流仍高；常与 **错误电平、域未关、工艺/温度** 相关。
- **动态**：随时钟/活动线性或超线性变化；优化 **duty、电压、频率** 更有效。

## 十、快速检查清单

**测量前**

- [ ] 供电路径唯一，无 USB/辅助电源偷电  
- [ ] 温度与输入电压已记录  
- [ ] 仪器量程、探头校零、接地方式确认  

**测量中**

- [ ] 触发源稳定，波形带标注（时基、探头、shunt）  
- [ ] 长平均与单次捕获各有一套数据  

**软件侧**

- [ ] wakeup_sources / suspend 日志已抓  
- [ ] 固件与内核版本、config 已记录  

**结论输出**

- [ ] 结论写清：**哪条轨、哪个时间窗、与哪个事件对齐、复现条件**
