# RK3588：现场测量与日志方法论

## 1. 文档目的

提供 **可复现** 的低功耗问题排查流程：**仪器、内核接口、日志与 trace**，供现场工程师与负责人统一语言。

**原因**：无统一方法时，团队容易陷入「猜驱动」；**电流 + 最后日志 + 二分** 可快速分层到 **硬件 / 固件 / 驱动**。

---

## 2. 仪器与环境

| 工具 | 用途 |
|------|------|
| 精密电源 / 纳安表 | suspend 电流、漏电对比 |
| 示波器 | DDR CKE/CK、PMIC PGOOD、唤醒脚毛刺 |
| 串口 | 最后 printk、固件早期 log（若可） |
| 热像仪 | 定位异常发热外设 |

**原因**：**电流已降** 说明大概率进了深睡路径；**电流不降** 优先查 **误唤醒或未睡**。

---

## 2.5 本仓库：`pm_test` 如何嵌在 `suspend_enter()` 里

**`kernel/power/suspend.c`** 在 **`suspend_devices_and_enter()`** 与 **`suspend_enter()`** 多处调用 **`suspend_test(TEST_*)`**；若 **`CONFIG_PM_DEBUG`** 打开，用户可向 **`/sys/power/pm_test`** 写入 **`none` / `freezer` / `devices` / `platform` / `processors` / `core`**，只跑到对应阶段即 **假装完成** 或 **提前返回**，用于 **隔离挂死在哪一层**。

与 `03` 引用的同文件片段衔接：**`suspend_test(TEST_DEVICES)`** 在 **`dpm_suspend_start` 之后**，**`TEST_PLATFORM`** 在 **`dpm_suspend_noirq` 之后**，**`TEST_CORE`** 在调用 **`suspend_ops->enter` 之前**（见 `suspend_enter()` 内联）。

**原因**：这是 **不依赖厂商工具**、**主线必带** 的最强分层手段之一（需内核打开 debug 配置）。

---

## 3. 内核 sysfs / debug（通用）

以下路径随 **内核版本与 config** 略有差异，以目标 BSP 为准。

- **`/sys/power/state`**：触发休眠。  
- **`/sys/power/pm_test`**：若启用，`freezer`、`devices`、`platform`、`processors`、`core` **逐级** 缩小挂死阶段。  
- **`/sys/kernel/debug/suspend_stats`**：成功/失败次数（若存在）。  
- **`/sys/kernel/debug/wakeup_sources`**：唤醒与 **阻止睡眠** 统计。  
- **`/proc/interrupts`**：中断风暴排查。

**原因**：`pm_test` 能快速判断问题在 **设备层** 还是 **平台/CPU 路径**。

---

## 4. 日志策略

1. **增大 log buffer**（`log_buf_len`）避免 **suspend 前日志被冲掉**。  
2. **串口不依赖图形台**，避免 **黑屏无 log**。  
3. **`initcall_debug` / `pm_debug_messages`**（若可用）：跟踪 **设备 suspend 顺序**。  
4. 记录 **精确时间点**：用户操作与 `dmesg` 时间戳对应。

---

## 5. Magic SysRq

- **`sysrq-w`**：显示 **blocked tasks**（系统仍部分存活时）。  
- **`sysrq-t`**：任务栈，查 **D 状态** 卡在哪个 `wait`。  
- **`sysrq-b`**：立即重启（最后手段）。

**原因**：**硬 hang** 时无 SysRq 则只能靠 **串口 + JTAG**。

---

## 6. ftrace / function_graph

- 对 **`__device_suspend`**、特定 `*_suspend`**、`rpm_suspend`** 设置过滤器。  
- **原因**：定位 **哪个驱动回调** 耗时过长或永不返回。

---

## 7. 二分法（驱动 / 模块）

1. **黑名单** 非必要模块启动。  
2. **`sysfs unbind`** 某总线下所有设备（谨慎，先文档化）。  
3. **最小 rootfs**（busybox + 必要驱动）。

**原因**：RK3588 外设多，**缩小复现集** 成本最低。
